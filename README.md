# Подготовка виртуальной машины

## Склонируйте репозиторий

Склонируйте репозиторий проекта:

```
git clone https://github.com/yandex-praktikum/mle-project-sprint-4-v001.git
```

## Активируйте виртуальное окружение

Используйте то же самое виртуальное окружение, что и созданное для работы с уроками. Если его не существует, то его следует создать.

Создать новое виртуальное окружение можно командой:

```
python3 -m venv env_recsys_start
```

После его инициализации следующей командой

```
. env_recsys_start/bin/activate
```

установите в него необходимые Python-пакеты следующей командой

```
pip install -r requirements.txt
```

# Сервис рекомендаций

FastAPI-микросервис для выдачи рекомендаций музыкальных треков.

## Структура модулей сервиса

| Модуль | Описание |
|--------|----------|
| `models.py` | Pydantic модели данных с валидацией (Field, Literal) |
| `store.py` | Хранилище данных с валидацией загрузки |
| `engine.py` | Движок рекомендаций с гиперпараметрами |
| `app.py` | FastAPI приложение и эндпоинты |
| `recommendations_service.py` | Точка входа для запуска сервиса |

## Возможности

- Выдача персонализированных рекомендаций на основе модели ALS
- Выдача топ-популярных рекомендаций для новых пользователей
- Учёт онлайн-истории пользователя для улучшения рекомендаций
- Смешивание онлайн и офлайн рекомендаций (blending)
- Валидация загружаемых данных
- Настраиваемые гиперпараметры через переменные окружения

## API Эндпоинты

| Метод | Эндпоинт | Описание |
|-------|----------|----------|
| GET | `/health` | Проверка состояния сервиса |
| GET | `/recommendations/{user_id}?k=10` | Получение k рекомендаций для пользователя |
| PUT | `/recommendations/{user_id}/feedback` | Добавление трека в онлайн-историю |
| GET | `/docs` | Swagger UI документация |
| GET | `/redoc` | ReDoc документация |

## Стратегия смешивания онлайн и офлайн рекомендаций

Сервис использует трёхуровневую стратегию выдачи рекомендаций в зависимости от наличия данных о пользователе:

### 1. Default (Топ-популярные)
**Условие:** Пользователь не имеет персональных рекомендаций (новый или редкий пользователь)

**Поведение:** Возвращаются топ-популярные треки, рассчитанные на основе общей статистики прослушиваний.

### 2. Personal (Персональные ALS)
**Условие:** Пользователь имеет персональные рекомендации, но нет онлайн-истории

**Поведение:** Возвращаются персональные рекомендации, рассчитанные офлайн с помощью модели ALS (Alternating Least Squares).

### 3. Blended (Смешанные)
**Условие:** Пользователь имеет персональные рекомендации И онлайн-историю

**Поведение:** Смешивание двух источников:
- **50% рекомендаций** — похожие треки на основе последних прослушанных (онлайн-компонента)
- **50% рекомендаций** — персональные ALS рекомендации (офлайн-компонента)

**Алгоритм смешивания:**
1. Из онлайн-истории берутся последние N прослушанных треков (настраивается через `RECENT_TRACKS_COUNT`, по умолчанию 5)
2. Для каждого трека находятся похожие треки (item-to-item similarity из ALS)
3. Похожие треки объединяются, исключая уже прослушанные
4. Добавляются персональные ALS рекомендации (исключая уже рекомендованные)
5. Если рекомендаций недостаточно, добираются из топ-популярных

### Преимущества стратегии:
- **Актуальность:** Онлайн-компонента учитывает текущие интересы пользователя
- **Стабильность:** Офлайн-компонента обеспечивает качественные базовые рекомендации
- **Robustness:** Fallback на топ-популярные для новых пользователей и редких случаев

## Запуск сервиса

### Предварительные требования:
1. Убедитесь, что виртуальное окружение активировано
2. Убедитесь, что файлы рекомендаций присутствуют в `recsys/recommendations/`:
   - `top_popular.parquet`
   - `personal_als.parquet`
   - `similar.parquet`

### Запуск:

```bash
# Стандартный запуск (порт 8000)
python recommendations_service.py

# Или с указанием порта через переменные окружения
SERVICE_PORT=8080 python recommendations_service.py
```

### Проверка работоспособности:

```bash
# Проверка здоровья сервиса
curl http://127.0.0.1:8000/health

# Получение рекомендаций для пользователя
curl http://127.0.0.1:8000/recommendations/12345

# Добавление трека в онлайн-историю
curl -X PUT http://127.0.0.1:8000/recommendations/12345/feedback \
     -H "Content-Type: application/json" \
     -d '{"track_id": 100}'
```

### Переменные окружения

#### Параметры сервера:
| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `SERVICE_HOST` | `0.0.0.0` | Хост для запуска сервиса |
| `SERVICE_PORT` | `8000` | Порт для запуска сервиса |
| `RECOMMENDATIONS_PATH` | `recsys/recommendations` | Путь к файлам рекомендаций |

#### Гиперпараметры движка рекомендаций:
| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `RECENT_TRACKS_COUNT` | `5` | Количество последних треков для онлайн-рекомендаций |
| `MAX_HISTORY_SIZE` | `100` | Максимальный размер онлайн-истории пользователя |
| `DEFAULT_K` | `10` | Количество рекомендаций по умолчанию |

### Примеры запуска с гиперпараметрами:

```bash
# Стандартный запуск
python recommendations_service.py

# С кастомными гиперпараметрами
RECENT_TRACKS_COUNT=10 MAX_HISTORY_SIZE=200 python recommendations_service.py

# Запуск через uvicorn (рекомендуется для production)
uvicorn app:app --host 0.0.0.0 --port 8000

# Запуск с hot-reload для разработки
uvicorn app:app --host 0.0.0.0 --port 8000 --reload
```

# Инструкции для тестирования сервиса

Код для тестирования сервиса находится в файле `test_service.py`.

## Описание тестов

Скрипт `test_service.py` выполняет тестирование сервиса для трёх типов пользователей:

1. **Пользователь без персональных рекомендаций**
   - Проверяет, что возвращается тип `default` (топ-популярные)

2. **Пользователь с персональными рекомендациями, но без онлайн-истории**
   - Проверяет, что возвращается тип `personal` (персональные ALS)

3. **Пользователь с персональными рекомендациями и онлайн-историей**
   - Добавляет треки в онлайн-историю
   - Проверяет, что возвращается тип `blended` (смешанные)
   - Проверяет, что рекомендации изменились после добавления истории

## Запуск тестирования

### Шаг 1: Запустите сервис (в отдельном терминале)

```bash
# Активируйте виртуальное окружение
. env_recsys_start/bin/activate

# Запустите сервис
python recommendations_service.py
```

### Шаг 2: Запустите тесты (в другом терминале)

```bash
# Активируйте виртуальное окружение
. env_recsys_start/bin/activate

# Запустите тестовый скрипт
python test_service.py
```

### Шаг 3: Проверьте результаты

Результаты тестирования выводятся в консоль и сохраняются в файл `test_service.log`.
